# 出图评估

每张返回的图先跑 `image_check.py`，再按下表逐项目检，写进下一轮 `roundN.md` 开头的评估表（方面 / 结果 / 说明）。结果只用"通过 / 部分通过 / 不通过"；"不通过"必须写出具体位置和下一轮怎么改。

## 1. 逻辑（先过这一组）

| 检查项 | 怎么看 |
|---|---|
| 流程完整 | 规格里的每个模块都在，顺序正确；没有多出的模块 |
| 箭头方向与连接 | 逐条核对起点、终点；数据流不回头；约束里"不连"的两处确实没连（例如外部数据与训练之间） |
| 结构事实 | 分支与汇合点、冻结 / 训练的部分、阶段覆盖的模块，和 `round1.md` 的结构事实表一致 |
| 数量 | 层数、格子数、网格行列数逐个数（R6） |
| 文字 | 每个标签拼写与规格一致；没有规格外的文字、标题、乱码；没有结果数字或内部代号 |
| 重复与矛盾 | 同一信息没有画两遍；图例和图内符号一致 |

## 2. 美术（逻辑全过后再看）

| 检查项 | 怎么看 |
|---|---|
| 视觉语言 | 没有阴影、发光、渐变、卡通；3D 只在模型行，投影方向、光向统一 |
| 层级 | 模型行最大、最先被看到；字号只有两级 |
| 模块感 | 流程行每一步是一个实色浅底方块；箭头约 2 pt |
| 配色 | 类别色只用于类别；方法色只用于方法通路；阶段色是浅底 |
| 灰度 | 类别色转灰度后仍能区分，或者有文字 / 位置区分（`image_check` 的 L* 差） |
| 影像位 | 全是空框，比例符合影像类型，没有假影像 |

## 3. image_check 结果怎么用

| 输出 | 处理 |
|---|---|
| `aspect … off`（ERROR） | 下一轮重申画布比例；不要自己裁图 |
| `dpi at … mm`（WARN） | 正常：生成图只是草稿，终稿在 Illustrator 里按草稿重绘或描摹 |
| `off the palette`（WARN） | 看列出的主色在哪个元素上，下一轮给该元素写色值（P5）。浅色底和抗锯齿边缘按色板色的浅色调算，不计入 |
| `not found in the image`（WARN） | 该类别色没用上或被画成别的颜色，下一轮点名 |
| `drawn as about …`（WARN） | 生图模型常把类别色画亮、画饱和（`#0072B2` 常变成 `#3F90F4` 一类的亮蓝）。下一轮在每个用到该类别的元素后面重写色值；仍漂就在 Illustrator 里统一改色 |
| `colour drift merged them`（WARN） | 色板本来可分，画漂以后灰度分不开；先按上一条修色 |
| `already in the palette`（WARN） | 色板本身灰度接近（Okabe-Ito 的绿和橙就是这样），每个类别色旁边必须有文字标签 |

## 4. 定稿条件

逻辑全部通过，美术没有"不通过"项，用户确认满意。定稿后交付：定稿图、最后一轮提示词、结构事实表，以及在 Illustrator 中要做的事（贴真实影像、按 180 mm 宽核对字号 ≥ 5–6 pt、必要时重绘为矢量）。

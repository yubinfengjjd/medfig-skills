# 提示词写法与迭代经验

经验来自一张三行研究设计 / 架构图的 7 轮迭代（ChatGPT 网页版生图）。编号供 SKILL.md 引用。

## P：写提示词

- P1 **结构 = 全局风格块 + 逐行内容 + 文字规则。** 逐行内容按从左到右编号写模块；每个模块写形状、填色、标签原文、和谁相连。
- P2 **标签原样加引号。** 图里出现的每个字都在提示词里加引号写出，最后用 TEXT RULES 说"只用这些文字"。没加引号的描述性文字，生成模型常会自己编标签。
- P3 **箭头写路径，不写"补一个箭头"。** 连续两轮说"add an arrow from X to Training"都被忽略；改成"从 X 圆柱顶部出发，从 Y 上方绕过去，进入 Training 框"后一次通过。凡是会和别的元素交叉的箭头都写绕行方向。
- P4 **"不连"要明说。** 防火墙这类约束要写反面："Nothing connects the external card to Training"。只写正面连接，模型会顺手补一条。
- P5 **颜色写色值，并且只给一个用途。** "light blue" 会被画成和类别蓝一样饱和的蓝；阶段色、角色色写低饱和十六进制值。
- P6 **数字只给设计数字**，并在 TEXT RULES 里列全。模型会自己补"AUC 0.95"之类的装饰数字。
- P7 **影像位写成空框**（浅灰、虚线、比例、"draw nothing inside"）。不写清楚就会画出假视网膜。
- P8 **结构从代码核对。** 文档写成"编码器 → 模块 A → 模块 B"串行，代码里编码器的输出同时送进 A、B 两路，在一个汇合算子处合并。示意图把方法最有辨识度的一步画错，比画丑更糟。
- P9 **用参考图时说清楚它的用途**："keep its content" 还是 "use its style only"。两张参考图同时上传时，分别写哪张管内容、哪张管画法。

## R：迭代

- R1 **先逻辑后美术。** 逻辑（流程、箭头、阶段、冻结）没通过之前，不改风格；风格问题攒到逻辑全过后统一改，避免一次改太多导致版式漂移。
- R2 **局部修改用同一对话，整体换风格开新对话。** 局部修改写"Keep everything else exactly as it is. Only make these changes:"，加编号列表，一轮不超过 6 条。换视觉语言时旧对话会把旧风格带过来，要新开对话，并上传上一轮的图作内容参考。
- R3 **保护已通过的部分。** 只改某几行时，在开头、中间、结尾各写一次"Row b: DO NOT CHANGE"，并列出它包含的元素。只写一次，模型常连这一行一起重画。
- R4 **已通过的项写进下一轮的"保持不变"。** 每轮评估表里"通过"的项，下一轮提示词末尾逐项点名保留。
- R5 **一项问题连续两轮没改好，就换说法**，不要重复同一句话：换成具体路径、具体坐标关系（"above / below / to the left of"），或拆成单独一轮只改这一项。
- R6 **模型数不清多的东西。** 12 层、16 个格子这类数量，要写"12 slabs: the first 6 … the last 6 …"并在评估时数一遍；数错是最常见的失败。
- R7 **每轮存档**：上一轮出图存为 `roundN-1_output.png`，提示词和评估写在 `roundN.md`，上传物放 `roundN_upload/`（`round_pack.py` 完成）。
- R8 **颜色会漂。** 即使提示词写了 `#0072B2`，生图模型返回的类别蓝也常是更亮的蓝（ΔE 约 24），类别绿偏青。`image_check` 报出后，在每个用到该类别的元素后重写色值；定稿前在 Illustrator 里统一改回色板值，和数据图保持一致。

## S：审美（顶刊示意图常见的差距）

- S1 粗渐变箭头、卡片套卡片、卡通人物、Title Case 多级粗体 → 商务信息图。
- S2 每个模块一样大、一样粗的标题 → 看不出主次；模型行应占约一半高度。
- S3 白底细框 + 细线箭头 → 太弱，模块散开以后看不出边界（流程行改用实色浅底方块）。
- S4 网络画成平面方框或几张纸片 → 看不出网络形状；用薄片、张量立方体、维度标注表达结构。
- S5 两行重复同一组信息（同一组中间量画两遍、任务框重复类别图例）→ 删掉一处，换成图例。

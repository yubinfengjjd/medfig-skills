# table_plan：表格规划

## 1. 每张表必填（A7）

| 字段 | 内容 |
|---|---|
| 编号与标题 | Table N / S-Table N + 一句话内容 |
| claim 或用途 | 这张表支撑哪个论断，或承担什么核对功能；登记正文引用节与位置 |
| 列 | 列名 + 单位 + 小数位；区间写类型（如 95% CI）与 bootstrap 方式 |
| 列数 / 行数 / 表注承载 | 逐表登记列数、数据行数（不含表头）、移入表注的内容与对应位置；超限时附设计理由与处置 |
| 来源 | 相对数据根的文件 + 列；多源时逐列写明 |
| 变换 | 只允许确定性变换（筛选、合并、四舍五入），写明 |
| 输出 | CSV + Markdown + LaTeX + source.json；Word 排版不在本技能范围 |

表格同样不出现内部代号（列名、表头、行名用描述名；代号对照可写在脚注）；脚注本来就放口径与限制，可以保留。

## 2. 主表 vs 附表

- 主表：通常 1–3 张，如队列 / 数据集特征、主结论性能表。
- 附表：每个主结论背后的完整数值、次要分析逐条结果（按科学问题组织、不用内部计划编号；阴性照实，附最小可达 P，E5）、消融与基线、稳健性、方法参数。
- 图中已展示的数值若读者需要精确值，给对应附表并在图注引用。

## 附表与主表的发表形态约束

以下六条适用于全部主表与附表；内部口径裁决、来源索引等过程元表若不进入投稿件，应明确标为过程材料。

1. **行列上限**：数据表以 ≤10 列、≤40 个数据行为基准（行数不含表头）。超限必须拆分或移出投稿件；移出者仅在正文或表注用一句话指向数据仓库 / 数据可用性材料。确需超限时，先在设计规格逐表写明理由及所保留信息的必要性，不以缩小字号代替精简。
2. **表体禁长文**：方法、处理规则、口径、注意事项等说明性文字一律进表注，表体只留数值与短标签。单元格文字建议 ≤50 字符，超过 50 字符必须移动或压缩；表注不受此单元格阈值限制。不得因压缩而删掉科学限定或改变数值。
3. **近常数列与可推导列**：近常数列不进表体，其少数例外移至表注或独立小表并保留准确对应关系，不能按多数值覆盖；全表同一值（如整列“—”）改表注一句。可由现有列推出的冗余列不保留：CI 上下限合为一列 `95% CI`，率可由计数 / 分母推出时不另列。每队列常数不得逐行重复，移到队列级小表或表注。
4. **被引用性**：每张主表、附表必须被正文引用；设计规格逐表登记“支撑论断”和“正文引用节 / 位置”。未被引用的表不得进入投稿件；资料归档不等于正文引用。
5. **转换登记**：保留原始源文件，只由源派生发表版；任何行 / 列删减、合并、文字外移，均在对应 `STxx.source.json`（主表对应 `Txx.source.json`）追加 `presentation_trim`，不覆盖既有溯源。登记源路径与 SHA256、保留 / 删除行列及筛选规则、合并清单与确定性规则、移入表注的原字段 / 内容和目标表注位置；整表移出时登记数据仓库去向。结合保留的完整源及转换规则必须能还原发表版，不手改原始 CSV，不改统计结果。
6. **规格模板**：规格 §5 表格清单必须增加“列数 / 行数 / 表注承载”三栏，并逐表填写支撑论断、正文引用位置、超限处置 / 理由及转换登记路径。设计检查不能由下游排版 WARN 替代。

`presentation_trim` 最小结构（按实际填写，保留现有 source.json 的其他键）：

```json
{
  "presentation_trim": {
    "source": {"path": "<完整源文件路径>", "sha256": "<源哈希>"},
    "rows": {"keep": "<行标识或确定性筛选规则>", "remove": "<移出行与去向；无则写无>"},
    "columns": {"keep": ["<保留列>"], "remove": ["<删除列及信息去向；无则空列表>"], "merge": [{"from": ["<原列>"], "to": "<新列>", "rule": "<确定性规则>"}]},
    "to_footnotes": [{"from": "<原字段 / 行>", "content": "<移出的完整说明>", "target": "<表号及表注位置>"}],
    "repository": "<仅整表移出时填写真实去向；未确定时登记待补>"
  }
}
```

## 3. 必备元表

### 3.1 口径裁决表（ST11 式，A8, E7）

每条语义裁决或相对上游的修正一行：

| # | 议题 | 冲突来源（文档:位置） | 权威依据 | 采用表述 | 旧 → 新 | 上游文件 SHA-256 旧 → 新 | 裁决人 |
|---|---|---|---|---|---|---|---|

- 第 2 步用户裁决的每条冲突都进此表。
- 规格新增的措辞修正（单位、定义、解读）也进此表。
- 上游文件若被修改，写旧 / 新哈希与备份位置；并注明"未改变任何预测、检验结果或数值"（若属实）。

### 3.2 图表来源索引（ST12 式，A7）

由全部 `*.source.json` 自动生成，每 panel 一行：

| 图 | panel | 输入路径 | SHA-256 | 行数 | 变换 |
|---|---|---|---|---|---|

- 必须在所有图、表导出之后，在主分支最后重建（依赖全部产物）。
- 规格里只声明它的存在与生成方式，不手填内容。

### 3.3 不可估计 / 未收集清单（ST09 式，A5）

| 项目 | 状态（NOT_COLLECTED / not estimable / out of scope） | 原因 | 来源 |
|---|---|---|---|

让缺口显式可见，不静默缺失。该清单若进入投稿件，也须遵守上述发表形态约束：状态与短标签留表体，原因和口径移入表注，并登记正文引用。

# 示例：把“自主”问成可验收的规则

本例提炼自用户提供的历史问答模式，并补充原记录容易遗漏的边界追问；以下答复是教学示例，不是用户对新项目的实际授权。NEJM 配色、每图 5–8 面板等历史偏好不作为本技能默认值。

用户：“我要 agent 自主完成论文图表，质量要好，我不懂编程。”

项目经理先读已有材料，再问两题：

**Q001 · 哪些事情可以让它自己决定？**
为什么问：这决定你会在哪些地方被叫回来，以及什么修改可能超出你的预期。
- A：只调外观；增删内容都找你——控制强，打断较多。
- B：外观和布局自己调；增删证据或改变结论找你——常规工作能继续推进。
- C：先列出每类操作，再逐项决定——更细，但要多一轮讨论。
推荐 B，作为明确权限的起点；你可以自由补充不放心的操作。

**Q002 · “质量好”最需要改善哪一处？**
为什么问：不同缺口需要不同的验收办法。
- A：读者看不清关键结果——先检查信息组织和可读性。
- B：图表和正文数字难以核对——先梳理证据与引用。
- C：还说不清——先看一份当前作品，指出具体不满意的位置。
没有看过作品时推荐 C；“美观”与“准确”不设成只能保一个的选择。

用户：“选 B，尤其删图必须问我。质量先看现有图。可我离线时希望它自己解决问题。”

项目经理记录删图确认要求，标记“离线自主”的适用边界未定，然后追问：

**Q003 · 如果你不在线，版面又放不下，而继续完成必须少一张图，你希望怎么办？**
为什么问：这里同时碰到了“删图必须问”和“离线自己解决”，需要明确这一种情况。
- A：保留全部内容，暂停这张图，继续独立工作——等待增加，内容不会被擅自删减。
- B：给你另存一份删减候选，保留原稿，等你回来选——能比较效果，但最终稿仍需等你。
- C：仅对你事先指定可删的内容自主删减——需要先明确范围。
推荐 B，前提是生成候选属于已允许的工作；当前边界确认前先保留原稿。

用户：“B 可以，最终稿不能自动删。”

记录结果：允许另存删减候选；最终稿删图仍需确认。它不授权改科学结论、外发数据或删原文件。

对应验收：构造离线且版面不足的情况，原稿保持不变，候选标明删减内容，最终稿保留待确认状态，其余独立工作可继续。

这个决定解决后，接着问质量问题；不要把权限澄清当成整份图表方案已经完成。

# 显式预设：公共数据单卡医学影像课题

只在用户明确选择此预设时启用。原示例为眼科；当前课题可以覆盖领域、模态、硬件与任何条件，并在 G1 记录覆盖，未确认的条件不自动视为生效。通用技能默认不启用。

## 原示例硬条件

- 仅公共数据，能直接下载或直接报名获取，不依赖邮件申请；有注册入口不等于不需审批，须核验步骤。
- 多数据集外部验证；G1 明确数量和独立定义，不把至少三个候选数据集等同多套可用外部测试。
- 单张 RTX 3080 Ti，运行内存充足为用户提供条件；实际显存/余量、输入规模和预算仍需核查，不由型号虚构实测。
- 仅课题设计与工程计划，不输出 Fig/Table 清单、成图规范或展示资产；必要逻辑流程、变量、伪代码和核查表允许。

## 原示例最低要求

研究背景明确临床痛点、可检验假设与影像关系。数据至少三个候选，逐项官方来源、获取步骤、模态、量级/单位、标注和外部划分。模型含主与辅助创新、组件、替代和理由；不能机械堆模块。

文献至少两个实际检索来源、明确近期窗口、多组查询式、纳入/排除、至少五篇核心准确书目和关联判断。逐步给数据库、时间窗、关键词、标准与证据格式。通用近五年约 10–20 篇现状扫描加 3–5 篇角色锚点是可覆盖工作量默认，与本预设最低门槛分别记录。

实验至少三类可命名对比，说明依据；主创新逐组件消融、完整训练/推理输入输出、epoch/早停、数据角色、推理 batch。成本给显存 GB、每轮/总时长、推理延迟的有依据上下限与场景假设，全部比较/消融/重复/搜索/重跑入账，不造数字。

评价覆盖至少三类适用指标（例如区分度、校准度和泛化/鲁棒性），明确统计方法、单位和区间/检验口径。可解释性、不确定性与临床转化各至少一个可检查方案及输出/评价。

固定主线按研究背景、数据、模型、实验、指标统计、可信性；增加明确范围、检索、一致性裁决和 agent 工程计划义务。最后独立可读的 Markdown 与聊天交付保持一致。

交叉一致性检查涵盖模态—输入、任务/标签—指标、文献差异—组件/实验；每条冲突注明类型、优先硬条件、降级与具体章节修订，修订后复核。无法满足时保留暂定和阻塞项，不改成隐含放宽或伪造通过。
